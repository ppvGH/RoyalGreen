# Exam readiness

[Documentation index](index.md) · [Development validation](development-validation.md)

`main` preserves the original project; `sac4ap` adds comments/documentation/tests without changing behavior; **sac4ap-dev** implements the subsequently authorized reliability, packaging and gameplay improvements. All retain the original 263-commit history.

| Criterion | Evidence |
| --- | --- |
| Version control / continuation | Protected tips, focused commits at actual dates, ancestry checks |
| Runnable by another user | Windows x64 assets/runtime package; native Linux/macOS source instructions |
| English documentation | README/index, installation/tutorial, API/architecture |
| Useful comments | Units, edges, geometry lifetime, skipped events, paths and destruction order |
| Separate tests | Catch2/Python cases with explicit expected/negative results |
| Processing integration | CPU GameSession and real context/resource checks |
| Reproducibility/automation | Immutable dependencies, native CI, ZIP/asset verification |
| Honest scope | Actual results separate from unperformed interactive checks/coverage gaps |

Present the **sac4ap-dev branch URL and exact commit** for the improved implementation. `sac4ap` describes the earlier adaptation. Check completed CI for the submitted commit and demonstrate on the exam machine. Complete the owner's attribution/license inventory before claiming reuse rights.

The course allows discussing projects shared with another exam and asks for agreement on suitability.
